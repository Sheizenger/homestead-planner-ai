# AGENTS.md

## What this repo holds

Two implementations of one product. `PRD.md` specifies the product; where it
disagrees with this file, this file wins and `PRD.md` is out of date.

- `src/` — the React/TypeScript web app. **Frozen.** It works, its known
  defects are catalogued in `BACKLOG.md`, and they are not being fixed. Its
  live job is to be the reference implementation the Swift port is verified
  against.
- `swift/` — the macOS SwiftUI app. New work happens here.

## Three layers

```
HomesteadEngine   pure Swift, no Apple frameworks. Planner, rules, geometry.
                  Builds and tests on Linux — no Mac involved.
HomesteadCore     @Observable view models: document state, variants,
                  selection, viewport, commands. No SwiftUI import.
Homestead         SwiftUI views. Read the model, draw it.
```

The agent building this app is **blind**: it runs on Linux and cannot render
SwiftUI. `Engine` and `Core` are verifiable by running tests; `Homestead` is
verifiable only through a Mac in CI. Logic that drifts into a view leaves the
half of the codebase the agent can actually check. Keep views thin — anything
holding a branch belongs in `Core`.

## Verification

`Engine` and `Core` tests run locally on Linux — `swift test` in `swift/`,
using swift-testing. A toolchain is not preinstalled; fetch the Linux release
from `download.swift.org` (Swift 6.1.2 on Ubuntu 24.04 is known to work, and
`Observation` builds there, so `@Observable` in `Core` costs nothing in
testability). The app target builds, tests, and screenshots on the macOS CI
runner only; read its job logs and download its screenshot artifacts to see
what the UI looks like.

**Golden fixtures** are the completion criterion for the port. `fixtures/`
holds layouts generated by the TypeScript engine across a matrix of plots,
modes, and seeds. Generation is deterministic (`mulberry32`,
`src/engine/placement.ts:62`), so the Swift engine reproduces them exactly.
A port stage is done when every fixture matches — not when the code reads
correct.

## Porting gotchas

Silent, and no config confesses them:

- **Sort stability.** The TS engine sorts on comparators that tie: equal
  corner distances (`generate.ts:101`), equal areas (`materials.ts:82`),
  equal severity ranks (`warnings.ts:244`). `Array.prototype.sort` is stable,
  Swift's `sort()` is not. Tied elements reorder, placement shifts, fixtures
  fail. Break every tie explicitly on a stable id.
- **Rounding.** `Math.round` rounds half toward +∞; Swift's `rounded()`
  rounds half away from zero. They disagree on negative coordinates. Port as
  `(x + 0.5).rounded(.down)`.
- **`mulberry32`.** Reproduce on `UInt32` with wrapping arithmetic (`&+`,
  `&*`) and identical shifts. Promotion to `Int` changes the stream, and with
  it every layout.

## Settled decisions

Decided deliberately. Honouring them costs less than re-deciding them.

- **Derived, never stored.** Analytics and warnings are computed from the
  document. The web app stores them on each variant and recomputes by hand in
  every mutator, so they go stale the moment the brief or the plot changes.
  Computed properties cannot go stale.
- **Generation adds.** Generating or re-rolling appends a variant and leaves
  the active one alone; edited variants carry a badge. Work the user did
  survives every generation.
- **The plan is a document.** `Codable` + `FileDocument`, one JSON format for
  both saving and export, carrying a `schemaVersion`. Analytics and warnings
  are written into the file so it reads standalone, and recomputed — never
  trusted — on open.
- **Undo is `UndoManager`, which means `Core` has none.** `UndoManager` is an
  Apple-platform type — it doesn't exist in swift-corelibs-foundation, so it
  cannot appear in anything this agent needs to build and test on Linux.
  `Core`'s mutators are therefore plain and undo-agnostic (`moveObject`,
  `deleteObjects`, ...); the app layer wraps each call with
  `undoManager.registerUndo`, the standard shape for a `ReferenceFileDocument`
  on macOS. Undo itself is consequently untested until a Mac runs it —
  narrow, App-layer-only surface, exactly the trade the three-layer split
  was built to contain.
- **A real viewport.** Pan and zoom are a `Viewport` (offset + scale) over a
  `Canvas`. North arrow and scale bar draw in screen space and stay put.
- **Locking selects.** A locked object or layer can be selected and
  inspected, and refuses to move, resize, or delete — with a visible answer
  when it refuses.
- **One `Canvas`.** ~300 objects as individual SwiftUI views will not hold a
  frame rate. Draw the plan in a single `Canvas`; overlay real views only for
  the selected object's handles.
- **Two locales**, `en` and `ru`, with a test asserting key parity.
- **macOS first.** iPad is a different input model, not a target flag.

## Working agreement

The user sets direction. Implementation, debugging, and verification belong
to the agent. Work arrives as a GitHub issue or a message, lands on a branch,
and reaches a PR whose description carries the CI screenshot contact sheet:
the user reviews pictures, not diffs.

`BACKLOG.md` holds everything known and not yet done — the port stages, the
frozen web app's defects, and the `PRD.md` sections that no longer match
reality.
